🧭 Echora 草稿文件架构 — 思维导图

📄 草稿文件系统（Draft File System）
配置编辑的「安全缓冲层」— 原文件永远安全
📁 文件A 是什么？
每个 AI 类型各有一个草稿文件
文件A = 原配置的「可编辑副本」
存储路径: ~/.echora/drafts/{aiType}.json
QClaw → drafts/qclaw.json | OpenClaw → drafts/openclaw.json | Hermes → drafts/hermes.yaml
🔄 文件A 的生命周期
阶段 1: 启动时初始化
Echora 启动
→
异步读取原配置文件
→
复制到 drafts/{aiType}.json
→
文件A 就绪
原配置文件只在此时被「只读」访问一次
阶段 2: 编辑中（用户操作）
用户修改参数
→
实时写入文件A
→
UI 实时刷新
所有修改只影响文件A，原配置完全不动
刷新/离开页面 → 文件A 内容保留（不丢失）
再次进入设置页 → 默认加载文件A
阶段 3: 保存（用户确认）
点击「保存」
→
文件A 内容
→
写入原配置文件
→
重启 Gateway
只有此时才写入原文件（不可逆操作）
阶段 4: 重置（用户放弃）
点击「重置」
→
原配置文件
→
重新复制到文件A
→
UI 刷新为原始值
文件A 被覆盖，所有未保存修改丢失
原配置文件始终安全
🔗 联动效果（文件A 的价值）
场景 1: 修改提供商 ID
用户将 "xiaomi-coding" 改为 "xiaoxiaomi"
→ 文件A 中所有 "xiaomi-coding/" 前缀自动更新
→ 完整路径: xiaoxiaomi/mimo-v2.5
→ Agent 主模型下拉框实时显示新路径
场景 2: 模型下拉框
Agent 主模型字段 → 改为下拉框
→ 从文件A 读取所有模型完整路径
→ 用户选择而非手动输入
→ 备用模型 → 多选填入
场景 3: 实时预览
修改上下文长度 400000 → 800000
→ 文件A 更新 → Agent 列表中的模型信息同步变化
→ 用户看到「修改后的效果」

│ ↑

↓ ↓
┌─────────────┐ ┌─────────────┐
│ 启动初始化 │ │ UI 编辑层 │
│ (一次性) │ │ (实时预览) │
└─────────────┘ └─────────────┘
🛡️ 安全保证
原配置文件：只在「启动复制」和「用户保存」时被访问
编辑过程中：所有操作只针对文件A
用户刷新页面：文件A 不丢失（持久化在磁盘）
用户点重置：文件A 被原配置覆盖（安全回滚）
不同 AI：各自独立的草稿文件（互不干扰）
❓ 待确认问题
Q1: 文件A 存储格式？JSON（QClaw/OpenClaw）vs YAML（Hermes）？还是统一 JSON？
Q2: 文件A 路径？~/.echora/drafts/{aiType}.json 还是其他位置？
Q3: 启动时如果原配置被外部修改（用户手动改了），是否重新覆盖文件A？
Q4: 多窗口场景？两个 Echora 窗口同时编辑同一个文件A？
Q5: 保存失败（文件被锁/权限不足）的回滚策略？
🕳️ 潜在坑位
坑 1: 编码问题
Hermes 用 YAML，QClaw/OpenClaw 用 JSON
方案: 文件A 统一用 JSON，保存时转回原格式
坑 2: 字段名映射
UI 显示名 ≠ 配置文件字段名（如 "上下文长度" ≠ "contextWindow"）
方案: 需要字段映射表（fieldMap）
坑 3: 嵌套对象
修改 provider name → 需要同步更新 models 中的 fullPath
方案: 实现「级联更新」逻辑
